## 1. Module-by-module technical summary

### 1.1 `edgegrid/` — shared foundation

- **`schemas.py`** — single source of truth for every wire message, pydantic
  `BaseModel` subclasses with `model_config = ConfigDict(extra="forbid")` (`_Base`,
  line 54). Nine message types (`_DOC_ORDER`, line 289): `NodeRecord`, `Heartbeat`,
  `JobRequest`, `Bid`, `JobAward`, `InferenceResult`, `Commitment`, `Verdict`,
  `SettlementRecord`. `_Base.canonical()` (line 64) produces deterministic
  sorted-key, no-whitespace JSON bytes with `signature` excluded, used for both
  signing and hashing. `shared/schemas.md` is generated from this file via
  `python -m edgegrid.schemas --emit-markdown` and is documented as never hand-edited.
  Full field-level schema is reproduced in §2 below.

- **`identity.py`** — ECDSA secp256k1 identity (`Identity` class, line 25). One
  keypair yields (a) a stable node id, (b) a checksummed Ethereum address
  (`Identity.address`, line 69–71) used as the on-chain settlement identity, and
  (c) signing capability (`sign_message`, line 84). Keys persist to
  `~/.edgegrid/<name>.key` at mode `0600` (`load_or_create`, line 42). `verify()`
  (line 98) and `verify_message()` (line 109) recover the signer's address from a
  signature and compare against a claimed address, returning `False` (never raising)
  on any malformed input.

- **`config.py`** — every tunable centralized, `_s/_i/_f/_b` env-override helpers
  (lines 17–21), `snapshot()` (line 72) redacting API keys but recording
  `..._KEY_SET` booleans, written into every run's `config.json`. Key defaults
  (verbatim from the file): `SAMPLE_RATE = 0.05`, `WARM_START_BONUS = 0.15`,
  `BID_WINDOW_S = 2.0`, `MIN_STAKE = 10.0`, `VALIDATOR_SLASH_SHARE = 0.80`,
  `TREASURY_SLASH_SHARE = 0.20`, `CHALLENGE_WINDOW_S = 3600.0`,
  `VALIDATOR_QUORUM = 1`, `PASS_THRESHOLD = 3`, `CENTRALIZED_USD_PER_1K_TOKENS = 0.002`,
  `GRID_USD = 0.001`, `OLLAMA_MODEL = "qwen3-vl:2b-instruct"`.

- **`da.py`** — local data-availability layer: namespaced blob store, binary Merkle
  tree with domain-separated leaf/node hashing (`_leaf_hash`/`_node_hash`, lines
  35–40, prefixes `\x00`/`\x01`), duplicate-odd-tail convention (line 53). Explicit
  **scope note in the module docstring** (lines 1–16): this reproduces Celestia's
  *interface and binding property*, not its availability guarantee under a
  decentralised validator set with DA sampling. `DALayer.verify_blob()` (line 233)
  is the full check a verifier runs: fetch, sha256 match, Merkle proof check.

- **`runlog.py`** — `RunLog` context manager (line 47). Every experiment run gets
  its own timestamped directory (`docs/results/<experiment>-<UTC-stamp>[-N]/`),
  never overwriting a prior run (collision-avoidance loop, lines 63–71).
  `config.json` captures full config snapshot + git SHA (`git_sha()`, line 28) +
  `git_dirty()` state. `manifest.json` records row counts, elapsed time, and
  `dropped` cases with reasons (`drop()`, line 145) — explicitly built as a reaction
  to a prior harness that silently deleted results and under-reported N (module
  docstring, lines 3–10).

- **`market.py`** — the auction implementation; see §3 for full mechanism detail.

- **`ledger.py`** — the off-chain settlement simulation mirroring the Solidity
  contracts exactly (module docstring, line 18). Integer wei accounting throughout
  (`WEI_PER_GRID = 10**18`, line 41); `check_invariants()` (line 571) asserts five
  separate exact-equality conservation identities. See §5 for the full state
  machine.

- **`weights.py`** — content-addressed model weight distribution over IPFS
  (`IPFSWeightStore`, `LocalWeightCache`, `WeightResolver`). Reimplements kubo's
  UnixFS/dag-pb CID computation from first principles (`cid_for_bytes`,
  `cid_for_file`, `cid_for_path`, lines 320–371) so that received bytes are
  **independently re-verified** against the requested CID rather than trusting the
  daemon (`IPFSWeightStore.get()`, line 595). `LocalWeightCache` (line 710) is a
  byte-budgeted LRU cache with file-lock-protected index (`fcntl.flock`, line 780).
  Explicitly unsupported and raising rather than degrading: HAMT-sharded
  directories, non-default chunkers, non-sha2-256 hashes, trickle DAGs
  (`UnsupportedDAG`, module docstring lines 30–33).

### 1.2 `discovery/` — Kademlia DHT + GossipSub market

- **`node.py`** — `EdgeGridNode` (line 122): one OS process = one libp2p host with
  (a) Kademlia DHT in SERVER mode holding this node's signed `NodeRecord` at
  `/edgegrid/node/<peer_id>` (`NodeRecordValidator`, line 72, checked at the DHT
  boundary on `put_value`/`get_value`), (b) a GossipSub mesh over four topics
  (`TOPIC_JOBS`, `TOPIC_BIDS`, `TOPIC_AWARDS`, `TOPIC_COMMITMENTS`), (c) a UDP
  heartbeat service. Documented gotchas in the module docstring (lines 13–30):
  `GossipSub.run()` must be started as its own service or the mesh never grafts;
  every inbound message is signature-checked against the wallet it claims
  (`_on_job`, `_on_bid`, `_on_award`, all reject-and-count rather than silently drop);
  the DHT routing table must be explicitly populated from connected peers
  (`_maintenance_loop`, line 564) or `put_value`/`get_value` silently degrade to a
  local dict. `run_auction()` (line 341) is the full auction lifecycle:
  broadcast → collect bids for `bid_window_s` → `market.evaluate()` → sign and
  publish the award.

- **`heartbeat.py`** — `HeartbeatService` (line 115): plain signed UDP datagrams at
  `C.HEARTBEAT_INTERVAL_S` (default 5s), deliberately decoupled from the DHT
  (module docstring lines 1–13: DHT = slow/replicated facts, heartbeat = liveness
  and the *warm model set*, which is what actually moves the auction via
  `WARM_START_BONUS`). `warm_models_of()` (line 269) returns `[]` unless the peer's
  claim is `verified` against its DHT-recorded wallet by default
  (`require_verified=True`) — an unverified peer cannot claim warmth and collect
  the 15% discount. Real machine state via `psutil` (`local_state()`, line 61),
  never fabricated; a `psutil` failure is reported as `healthy=False`, not zeros
  that look like a genuine reading.

### 1.3 `inference/` — streaming Ollama engine

- **`engine.py`** — `InferenceEngine` (line 177). Module docstring (lines 1–30)
  states the whole point: the prior implementation used `stream=False`, making TTFT
  *structurally unmeasurable* (the HTTP response doesn't exist until generation
  finishes). `stream_tokens()` (line 324) consumes Ollama's NDJSON stream and
  stamps `ttft_ms` at the first chunk with non-empty `response` (line 387–388).
  Token counts come from Ollama's own `eval_count`/`prompt_eval_count`
  (`_absorb_final`, line 435), never `len(output.split())`. A counter the runtime
  doesn't send is named in `missing_counters` rather than defaulted to 0
  (lines 444–459). `run()` (line 489) raises `EmptyOutputError` on zero tokens and
  `OllamaProtocolError` if `eval_count` is missing while output is non-empty
  (lines 514–522) — it will not sign a token count the runtime didn't report.
  Warmth is read live from `/api/ps` (`is_warm()`, line 274), never cached locally,
  because eviction is out of this process's control and a stale warm flag
  mis-prices a bid. Six named exception types for distinct failure modes
  (`OllamaUnavailableError`, `ModelNotFoundError`, `InferenceTimeoutError`,
  `OllamaProtocolError`, `EmptyOutputError`).

### 1.4 `verification/` — LLM-as-a-Judge, validator pool, fraud injection

- **`validator.py`** — `ValidatorPool` (line 120), a three-step audit ordered
  cheap-first (module docstring lines 10–23): (1) `should_audit()` — deterministic
  keyed-hash sampling at `C.SAMPLE_RATE` (default 5%), `audit_score()` (line 43) is
  `sha256(seed + job_id)` truncated to a uniform float; (2) DA fraud proof —
  recompute the blob's sha256 and check its Merkle inclusion proof
  (`verify_commitment()`, line 149); a mismatch is a **fraud proof**, needs no
  judge call, and is objectively certain; (3) quorum judging — only runs if the DA
  check passes. `tally()` (line 175): FAIL is checked before PASS, so at
  `quorum <= n/2` a single dishonest validator can force a slash (explicitly
  documented, line 178). ERROR verdicts never count toward either side; a pool
  that can't reach quorum returns ERROR (line 190), which callers must treat as
  "do not settle," never as innocent or guilty.

- **`panel.py`** — `JudgePanel` (line 256): N *heterogeneous* judges (different
  model families, not copies) voting on one answer, duck-typed to slot into a
  `ValidatorPool` seat. Three quorum rules (`QUORUM_RULES`, line 53):
  `majority` (strict majority of members that returned a usable score, tie = ERROR),
  `unanimous` (any split = ERROR), `any_fail` (one FAIL condemns — conservative,
  used for slashing). `ThinkingAwareJudge` (line 56) is a documented workaround: a
  reasoning model (`qwen3-vl:8.8B`, tested against ollama 0.30.7) put its entire
  answer in the `thinking` field with `response=""`, causing 0 usable verdicts
  through the base `Judge`; this subclass sends `think=False` and falls back to
  `thinking` when `response` is empty, marking the Verdict's `reason` when it does
  (lines 62–87). `cohens_kappa()` (line 405) returns `None` — not 0.0 — when
  chance agreement is exactly 1.0 (both raters used one label throughout),
  because the statistic is genuinely undefined there.

- **`fraud_injector.py`** — four corruption strategies (`STRATEGIES`, line 31):
  `swap_incorrect`, `negate`, `hallucinate_entity`, `random_topic`. **Validity
  checking** (`check_validity()`, line 199) is the addition documented as fixing a
  prior bug: a corruption can accidentally produce a *true* statement (e.g. a
  `random_topic` draw whose answer happens to also answer this question, or a
  double-negation), and scoring such an item as fraud then counting the judge's
  correct PASS as a "missed detection" understates the judge. `similarity()`
  (line 73) is symmetric Jaccard over content words, zeroed whenever polarity
  differs (`polarity()`, line 62, counts negation markers mod 2) — deliberately
  symmetric rather than containment-based, because containment wrongly discarded
  every `hallucinate_entity` corruption (module docstring lines 79–90 in
  `similarity`'s own docstring). `LEXICAL_THRESHOLD = 0.80` (line 192).

- **`evaluator.py`** (`Judge` base class) — read only by reference from
  `panel.py`/`validator.py` imports in this pass; not independently opened. Flagged
  in §7.

### 1.5 `contracts/contracts/` — Solidity settlement layer

Five contracts, Solidity `0.8.24`, no OpenZeppelin dependency (in-repo `Owned` +
single-slot-mutex `ReentrancyGuard`, `Auth.sol`, documented as a reproducibility
tradeoff, lines 5–8):

- **`NodeRegistry.sol`** — the only place stake is created or destroyed. `stake()`
  (line 130), `requestUnstake()`/`claimUnstake()` (lines 144, 163) with an
  `unbondingPeriod` during which collateral **stays slashable**
  (`slashableOf()` = active + unbonding, line 246) — explicitly closing the
  front-running-a-fraud-proof hole. `slash()` (line 189) is `onlySlasher`-gated
  (only the `VerificationContract` may call it — the earlier sketch had no access
  control at all, module docstring lines 10–19), consumes active stake before
  unbonding, and returns `fullyCovered=false` rather than silently rounding when
  collateral is insufficient. `VALIDATOR_SLASH_BPS = 8_000` (80%, line 41,
  constant, matches `edgegrid.config.VALIDATOR_SLASH_SHARE`).

- **`Marketplace.sol`** — escrow state machine exactly mirroring
  `EscrowState` in `schemas.py`/`ledger.py`:
  `NONE → OPEN → AWAITING_VERIFICATION → {SETTLED | SLASHED}`, and
  `OPEN → REFUNDED` on award timeout. `release()` (line 145) is **permissionless**
  — "the honest outcome must not depend on any privileged party staying online"
  (line 143). All payouts are pull-payment (`withdrawable` mapping + `withdraw()`,
  line 201) guarded by `nonReentrant`, explicitly because "a malicious requester or
  provider contract cannot re-enter the settlement path" (lines 21–23).

- **`VerificationContract.sol`** — the only address permitted to call
  `Marketplace.refundOnFraud` and `NodeRegistry.slash`. Two fraud-confirmation
  paths, both explicit about their trust model (module docstring lines 14–24):
  `proveDataMismatch()` (line 204) is **trustless and permissionless** — the EVM
  itself recomputes the Merkle root via `_computeRoot()` (line 273, byte-compatible
  with `edgegrid/da.py`'s scheme: `sha256(0x00||data)` leaves,
  `sha256(0x01||left||right)` nodes) and reverts `NoMismatch` if the revealed blob
  actually matches, so an honest provider cannot be slashed by a well-formed but
  truthful challenge (line 199). `submitVerdict()` (line 226) is an **oracle** call,
  gated `onlyValidator` (allow-listed *and* actively staked, `onlyValidator`
  modifier line 132) — "the earlier sketch let any address write any verdict; that
  is the hole this closes" (line 23).

- **`ModelRegistry.sol`** — binds a model id (keccak256 of the name) to a content
  hash and IPFS URI, versioned and revocable. Explicitly stated as newly
  implemented: "the Phase-1 design names this contract; nothing implemented it.
  Without it `JobRequest.model` is an unenforced string" (lines 11–13). This is the
  on-chain half of `edgegrid/weights.py`'s CID resolution.

- **`Auth.sol`** — `Owned` (single-owner access control) and `ReentrancyGuard`.

## 3. Auction mechanism — exactly as implemented (`edgegrid/market.py`)

This is a **procurement (reverse) auction**: providers bid the price they want to
be paid, the requester picks the lowest acceptable bid, and under a Vickrey rule
the winner is paid the **second-lowest** price (module docstring lines 1–8).

1. **Eligibility (`exclusion_reason`, line 95)**, checked hard-constraints-first so
   the reported reason is the most fundamental: job-id match →
   signature valid (`verify_message`) → `price > 0` and finite → `tier >= min_tier`
   → `estimated_ttft_ms <= max_latency_ms` and finite → `price <= max_price`. Any
   failure scores the bid `math.inf` — "cannot win," not "expensive."

2. **Warm-start discount (`discount_factor`, line 79; `effective_price`, line 90)**:
   a warm bid's *score* (never its payout) is multiplied by
   `1 - WARM_START_BONUS` (default 0.15, clamped to `[0, 0.99]`). Ranking uses
   `effective_price`; the clearing price never does.

3. **Ranking (`ScoredBid.sort_key`, line 135)**: `(effective_price, estimated_ttft_ms,
   bidder_peer_id)` — deterministic total order, ties broken by TTFT then peer id.

4. **Revision handling (`_revision_key`, line 166; `rank_bids`, line 179)**:
   duplicate bids from one peer collapse to the newest revision by
   `(created_ms, sha256(canonical_bytes))` — the bid's own signed claim, never
   arrival order — "so the same bid set replayed from a CSV in a different row
   order can pay a different price" is explicitly ruled out (line 175). Superseded
   copies are reported with `REASON_SUPERSEDED`, not silently dropped.

5. **Clearing price (`evaluate`, line 211)**:
   - ≥2 eligible bids: `threshold = ranked[1].effective / discount_factor(winner)`,
     `clearing = min(threshold, job.max_price)`. With no warm winner this reduces
     exactly to the runner-up's own price (plain Vickrey). A warm winner is paid
     *above* the runner-up's sticker price by exactly the 15% handicap, so in
     effective terms it still pays the runner-up's score (module docstring lines
     19–31, with the algebra given explicitly).
   - Exactly 1 eligible bid: `clearing = job.max_price` — the requester's own
     declared reserve, not the winner's own bid (a first-price rule here would
     destroy truthful bidding for the single-bidder case where the incentive to
     shade is largest — lines 33–39).
   - 0 eligible bids: `award = None`. Never falls back to "cheapest ineligible
     bid" (`second_price_auction`, line 255).

6. **Invariant, stated in the module docstring (line 29)**:
   `winning_bid_price <= clearing_price <= max_price`, always.

7. **Determinism**: pure function, no sockets/clock/config mutation — "deterministic
   given the same *set* of bids, in any order" (line 42). `AuctionOutcome.n_accounted`
   must equal `n_received`, asserted via `AssertionError` if a bid is neither ranked
   nor rejected (`evaluate`, lines 217–223).

## 4. Verification flow — exactly as implemented

Three-step, cheap-check-first pipeline in `verification/validator.py`
(`ValidatorPool.audit`, line 195; see §1.4):

1. **Sampling trigger**: `should_audit(job_id, seed, rate)` (line 50), default
   `rate = C.SAMPLE_RATE = 0.05`. Deterministic keyed hash of `(seed, job_id)`
   (`audit_score`, line 43) — reproducible by anyone with the seed, unpredictable
   to a provider without it.

2. **DA check (objective, no judge call)**: `verify_commitment()` (line 149) —
   `DALayer.verify_blob()` recomputes sha256 and checks the Merkle inclusion
   proof. A mismatch returns `VerdictKind.FAIL` with `fraud_proof=True` directly —
   `judge_calls=0` (lines 212–219). No DA layer configured → the commitment is
   explicitly **not** verified (`blob_verified=False`), never defaulted to true
   (lines 202–208, with the note that an earlier version of this code wrongly
   claimed verification here).

3. **Quorum judging (only if DA passes)**: each validator's `Judge.score()` is
   called (`_vote`, line 163; threaded if >1 judge), producing a `Verdict` with
   `verdict ∈ {pass, fail, error}` (`VerdictKind`, `schemas.py` line 224).
   `tally()` (line 175): FAIL wins if `n_fail >= quorum`, else PASS if
   `n_pass >= quorum`, else ERROR. `VALIDATOR_QUORUM` defaults to 1
   (`config.py` line 54).

**What pass/fail/error mean in code**: `pass` = quorum of validators scored above
the pass threshold (`PASS_THRESHOLD = 3` on a 1–5 rubric, `config.py` line 42, used
in `panel.py`'s `pass_threshold` and implicitly in `Judge` — not independently
verified in `evaluator.py` in this pass, see §7); `fail` = quorum voted fail, or a
DA fraud proof fired; `error` = judge unreachable, unparseable, or no quorum
reached — **never** silently converted to pass or fail anywhere in `validator.py`,
`panel.py`, or the `VerdictKind` enum's own docstring (`schemas.py` line 227:
"NEVER silently a pass or fail").

`JudgePanel` (§1.4) is a second, independent verification path used in a later
experiment: heterogeneous judges (different model families), three alternative
quorum rules (`majority`/`unanimous`/`any_fail`), explicitly built to test whether
model diversity — not just repeated sampling of one model — improves fraud
detection (module docstring lines 9-21).

## 5. Settlement logic — exactly as implemented

**Off-chain simulation** (`edgegrid/ledger.py`, `Ledger` class, line 191) and
**on-chain** (`contracts/contracts/{NodeRegistry,Marketplace,VerificationContract}.sol`)
implement the identical state machine and split, verified by an on-chain
integration run (§6.4).

- **Stake**: `MIN_STAKE = 10.0` GRID (`config.py` line 58; `NodeRegistry.sol`
  `minStake`, constructor-set). A node is "active" iff
  `stake > 0 and stake >= min_stake` (`Ledger.is_active`, line 304;
  `NodeRegistry.isActive`, line 241).

- **Escrow state machine** (identical in `ledger.py` lines 18–27 and
  `Marketplace.sol` lines 8–13):
  ```
  OPEN --record_commitment--> AWAITING_VERIFICATION
  AWAITING_VERIFICATION --release after challenge deadline--> SETTLED
  AWAITING_VERIFICATION --confirm_fraud--------------------->  SLASHED
  OPEN --cancel after award timeout------------------------>  REFUNDED
  ```

- **Challenge window**: `CHALLENGE_WINDOW_S = 3600.0` (1 hour, `config.py` line 55).
  `release()` (both `ledger.py` line 362 and `Marketplace.sol` line 145) is
  **permissionless** and reverts if called before the deadline.

- **Fraud confirmation, two paths** (`_confirm_fraud`, `ledger.py` line 463;
  `VerificationContract._confirmFraud`, Solidity line 255):
  1. `prove_data_mismatch()` — trustless, permissionless, requires a valid Merkle
     inclusion proof under the committed root plus a hash mismatch; reverts/raises
     if the revealed blob actually matches (no false slashing of honest providers).
  2. `submit_verdict()` — oracle path, restricted to allow-listed *and* actively
     staked validators (`NotValidator`/`ValidatorNotStaked` in Solidity,
     `NotValidator` in Python).

- **Slash amount and split**: `slashed = min(target, active_stake + unbonding_stake)`
  (`ledger.py` lines 473–478; `NodeRegistry.slash`, Solidity lines 189–223).
  `fully_covered = (slashed == target)` — under-collateralization is reported, never
  silently rounded. Split: `VALIDATOR_SLASH_SHARE = 0.80` /
  `TREASURY_SLASH_SHARE = 0.20` (`config.py` lines 59–60), stored as basis points
  (`validator_bps`, `ledger.py` line 214; `VALIDATOR_SLASH_BPS = 8_000`,
  `NodeRegistry.sol` line 41). `treasury_amount = slashed - validator_reward`
  (remainder, so no dust is lost — `ledger.py` line 490).

- **Unbonding**: stake requested for withdrawal stays slashable for
  `unbonding_period_s` (defaults to `CHALLENGE_WINDOW_S`, `ledger.py` line 201) —
  explicitly closing a front-running hole (`NodeRegistry.sol` lines 16–17).

- **Value conservation**: `Ledger.check_invariants()` (line 571) asserts five exact
  integer-wei identities (stake ledger vs accounting, unbonding ledger vs
  accounting, credited ledger vs accounting, escrow ledger vs accounting, total
  deposited = stake + unbonding + escrow + credited + withdrawn, escrow outflow =
  payout + refund, slash split = validator_reward + treasury). Any mismatch raises
  `InvariantViolation`, documented as never to be caught (line 111).

## 7. Open questions — must be resolved before citing the affected material

1. **RESOLVED.** `docs/PAPER_DRAFT.md` cites stale numbers from the *Phase-1* run
   (83.87% precision / 97.5% recall), which `docs/report/ch8_results.md` §8.4.3
   explicitly identifies as a **misdiagnosed generator problem, not a judge
   result**: Phase-1's "honest" answers came from a weak hosted model
   (`allam-2-7b`, via Groq — see `docs/harshit_work_26_08_2026.md`) whose outputs
   were themselves often factually wrong; the judge correctly flagged them as
   inaccurate, and those correct judge calls were then scored as false positives
   because the harness's honest/fraud labelling conflated "not deliberately
   corrupted" with "true." That produced the alarming 75% false-positive rate
   Phase-1 reported and blamed on the judge.

   The `verification-20260902T121801Z` run quoted in §6.4 above is the **corrected,
   canonical run**: same judge model/family, same rubric, same `PASS_THRESHOLD=3`,
   but honest answers now come from `--honest-source local` (the real edge node
   generating its own answers) rather than a separate weak hosted generator. Under
   that fix: **100% precision, 0% false-positive rate, 65% overall recall** — and
   recall itself is revealed by `ch8_results.md` §8.4.4–8.4.5 to be sharply
   bimodal by corruption strategy: 95–100% on lexically-obvious corruptions
   (`hallucinate_entity`, `random_topic`) vs. 30–35% on semantically-subtle ones
   (`negate`, `swap_incorrect`) that score confidently (mean 3.80–4.05/5, a full
   point *above* the pass threshold) rather than hovering uncertainly near it —
   ruling out "just move the threshold" as a fix. **`docs/PAPER_DRAFT.md`'s
   verification numbers are superseded and must not be used**; any paper draft
   must use the `ch8_results.md` §8.4 figures, and should report the Phase-1→
   corrected-run discrepancy itself as a methodological finding (a judge-accuracy
   evaluation is confounded with its honest-answer generator's accuracy unless the
   generator is named and recorded per row) — `ch8_results.md` §8.4.3 already
   states this generalizable lesson explicitly and it is worth keeping in Related
